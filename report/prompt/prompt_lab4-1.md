# 操作系统 Lab4 功能模块一——AI 使用提示词

## 使用目的

借助 AI 阅读实验手册与小组最新版代码，辅助完成并核验 Lab4 功能模块一，同时整理代码原理、测试过程和答辩问题。AI 仅作为代码分析、实现建议、调试和知识讲解工具，最终内容需要结合实验手册、实际代码和运行结果进行确认。

## 主提示词

```text
你现在是我的操作系统实验助教。我们小组正在完成操作系统 Lab4，实验由三个练习和 challenge 组成，我负责“功能模块一”。请基于实验手册、仓库 lab4 分支的最新版代码以及仓库原有框架，帮助我完成并核验模块一。

我的基础比较薄弱，请严格遵守以下要求：

1. 首先完整阅读实验手册中 Lab4 的目标、三个练习、challenge、评分点和所有“无需修改但需要理解”的相关文件，不要仅凭函数名猜测任务。
2. 明确指出功能模块一对应实验手册中的哪一部分、需要实现哪些功能、涉及哪些源文件、函数、结构体和调用关系，并说明它与模块二、模块三的边界。
3. 先检查 lab4 分支当前代码状态和已有提交，判断模块一是未完成、部分完成还是已经完成。不要重复修改队友已经完成的模块，也不要覆盖无关代码。
4. 若模块一尚未完成，请尽量使用实验框架已有接口进行最小范围实现；保留原有编码风格，不修改公开函数签名，不使用与实验目标无关的大规模重构。
5. 对每一处修改说明：
   - 文件路径；
   - 函数或代码位置；
   - 修改前存在的问题；
   - 修改后的工作流程；
   - 为什么这样实现；
   - 与其他模块如何配合。
6. 重点解释操作系统原理，不能只给代码。请用适合初学者的方式说明关键数据结构、状态变化、控制流、资源所有权、异常处理以及可能出现的边界情况。
7. 检查是否存在空指针、越界、资源泄漏、重复释放、错误状态转换、并发安全或中断上下文使用不当等问题。
8. 根据仓库实际 Makefile 和实验工具给出完整运行命令，不要编造命令。至少包括：
   - 切换并更新 lab4 分支；
   - 清理旧构建；
   - 编译；
   - 自动测试或 grade；
   - QEMU 运行；
   - 退出 QEMU 的方法。
9. 实际运行能够执行的测试，并区分“已经实际验证”与“理论预期”。如果测试失败，请先定位根因，再提出最小修复方案，不要把预期结果写成真实结果。
10. 不得删除或覆盖队友代码，不得使用 git reset --hard 等破坏性命令，不得私自修改远程仓库。需要提交或推送时，先列出差异并说明影响。
11. 最后按以下结构输出：
   A. 模块一任务边界；
   B. 相关文件与调用链；
   C. 实现或检查结果；
   D. 完整运行命令及预期现象；
   E. 实际测试结果；
   F. 高频答辩问题与简短答案；
   G. 仍需人工确认的事项。

答辩问题请优先选择性价比高、容易被追问的内容。每个答案先给一句可以直接背诵的结论，再给简短解释。若实验手册和当前代码不一致，以实验手册的要求为验收依据，并明确指出差异。
```

## 代码讲解追问提示词

```text
请只讲解 Lab4 功能模块一的代码。按照“入口函数 → 关键调用 → 数据结构变化 → 返回结果”的顺序，用纯小白能理解的语言逐步说明。每讲一个函数，都回答以下问题：

1. 谁调用它？
2. 参数分别是什么？
3. 它读取或修改了哪些状态？
4. 正常情况下返回什么？
5. 失败或边界情况下如何处理？
6. 为什么不能省略这一步？
7. 助教最可能从这一段追问什么？

不要泛泛介绍教材概念，所有解释都必须对应当前仓库中的真实文件名、函数名和代码。
```

## 测试与调试提示词

```text
请根据当前 lab4 分支和 Makefile，为功能模块一制定最小但完整的测试方案。先列出每个测试验证的功能，再给出可复制的命令、预期输出和失败时的排查顺序。请实际检查编译日志和测试输出，不能仅凭“编译成功”判断功能正确，也不能把模拟输出当成真实测试结果。
```

## 答辩准备提示词

```text
请根据实验手册和 lab4 最新代码，为我整理功能模块一的高性价比答辩题。我是纯小白，请按“必背、常见追问、代码定位”三档整理。每题包含：

- 助教可能怎样问；
- 一句话背诵答案；
- 20 秒解释；
- 对应文件和函数；
- 容易说错的点。

优先覆盖模块作用、调用链、关键数据结构、状态变化、资源释放、异常路径、测试方法以及它与模块二和模块三的关系。
```

## 使用说明

使用时应同时向 AI 提供以下材料：

1. 操作系统实验手册中 Lab4 的完整内容；
2. 小组 GitHub 仓库地址及 lab4 分支；
3. 小组分工说明，明确本人负责功能模块一；
4. 最新编译、运行或自动测试输出；
5. 如有报错，提供完整报错文本及对应命令。

提交 AI 使用记录时，应保留真实的问题、分析过程和验证结果，不应把尚未运行的预期结果描述为已经通过。
